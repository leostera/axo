## Owning client-state change

The former view-global `chatDraft` and unconditional pre-result clear are removed. `AxodChatComposer` binds through an immutable rendered logical conversation key: **machine/workspace/session/pane/chat**. Current and runtime-birth generations are deliberately not draft identity; exact resume can retain editable text. A submission independently captures the **complete current Pi target**, original command ID, trimmed plain text and an immutable editor revision. A restored draft is never command permission.

`AxodChatDrafts` bounds the in-process cache to 32 conversations, 64 KiB UTF-8 per draft and 1 MiB aggregate text. Capacity refuses replacement instead of truncating/evicting unsent text. A refused editor write blocks submission of the older stored value while an AppKit field editor may still display its unaccepted replacement. Empty text releases its slot. Source/session/chat isolation, capacity and exact-resume behavior have pure client-state evidence, not durable-storage or actual multiwindow evidence.

- Rejection/known local no-send preserves text; prepared, missing, mismatched and unknown evidence cannot clear it or permit replay.
- A validated **dispatched** receipt clears only the original unchanged revision. Later edits and edit-away/edit-back ABA changes survive; dispatch acknowledgement does not prove execution.
- Matching original receipt lookup can resolve a retained in-process submission; null/prepared/mismatched receipts cannot. No new command is generated by restoration/reconciliation.
- Editing stays local during pending commands/questions. Send remains fenced against the captured and current readiness/interaction; there is no automatic queue. Rendered cancel and question-answer actions also capture their source target rather than operating on another selection.
- Opaque/non-Data pending preferences block dispatch and are preserved. Clearing a saved hint now requires the exact original command, target and operation. A generation token prevents a superseded async mutation from releasing another mutation's busy state.
- Before a request and after its await, the coordinator validates the captured operation/peer/private endpoint. Result application remains scoped; selection never retargets the original request.

`AxodPiMutationRequest` parses normal/steer/cancel/answer into closed protocol DTOs and checks the complete encoded JSON-RPC frame **before** saving a potentially-dispatched hint. Invalid/slash/overlong text, absent/zero interaction/question/option IDs and encoded overflow fail locally without creating an unknown command. The unchanged limits are **48 KiB plain Pi message bytes / 64 KiB control RPC frame**, not the terminal plane's separate encoded bound. A generated UUID in this pure framing estimate is only fixed-width byte accounting; the SDK independently owns actual hop correlation. No fallback Pi engine, extra public method or canonical-history writer was added.
