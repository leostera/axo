### Evidence labels

Implementation and validation are separate axes:

- **Implemented:** current source exposes the capability; not a claim of operational acceptance.
- **Partial:** source supplies only part of the required workflow.
- **Missing:** the required capability/path is absent.
- **Blocked:** a particular action or acceptance drill requires a decision, safe ownership proof, permission, or unavailable capability. Other work may proceed after scope approval.
- **F:** historical unit/property/owned-fixture evidence, with the limitations in the evidence index.
- **N:** native evidence; isolated hidden-window checks are labeled as such, not full-workbench acceptance.
- **L:** deployed/live/device evidence, only for the exact recorded versions and scenarios.
- **Unvalidated:** no passing evidence for the required current actual-surface workflow.
- **Deferred / superseded / proposed:** tracked separately below; none is silently promoted into supported scope.

A test file existing, a checkmark in an older ledger, a skipped test, or a built app is not a passing acceptance result. Rows below identify dependencies and acceptance procedures even where implementation is missing.
