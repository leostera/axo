### Evidence labels

Implementation and validation are separate axes:

- **Implemented:** current source exposes the capability; not a claim of operational acceptance.
- **Partial:** source supplies only part of the required workflow.
- **Missing:** the required capability/path is absent.
- **Blocked:** a particular action or acceptance drill requires a decision, safe ownership proof, permission, or unavailable capability. Other work may proceed after scope approval.
- **F:** historical unit/property/owned-fixture evidence, with the limitations in the evidence index.
- **N:** native evidence; isolated hidden-window checks are labeled as such, not full-workbench acceptance.
- **L:** deployed/live/device evidence, only for the exact recorded versions and scenarios.
- **Unvalidated:** no passing evidence for the required current actual-surface workflow.
- **Deferred / superseded / proposed:** tracked separately below; none is silently promoted into supported scope.

A test file existing, a checkmark in an older ledger, a skipped test, or a built app is not a passing acceptance result. Rows below identify dependencies and acceptance procedures even where implementation is missing.

## Current source and route facts

1. `apple/project.yml` builds the Mac target from `AxoMacAxod` plus selected settings/voice/sidebar sources. It does **not** link GhosttyKit or compile the old terminal/split host into that target. `AxodWorkbenchView.swift` explicitly says terminal attachment is unavailable.
2. `axod/src/local.rs` exposes `/v1/rpc` as a control-only listener. `runtime.rs` and `terminal.rs` have internal attachment/input/resize/backlog machinery, not a public native terminal transport. The 8-KiB raw backlog is not a VT snapshot.
3. `panes/rpc.rs` still requires an approved `profileId` whose canonical cwd matches the work session. Default local Pi policy works without profiles, but that does not authorize or implement the required default regular shell.
4. `protocol/src/contracts.ts` and the compiled package currently contain **20 shared daemon methods and 5 local-only methods**. Export inspection agrees with source. Older 19/21-method counts are historical.
5. Local-only methods are `axo.workspace.createLocal`, `axo.session.pane.add`, `axo.session.pane.remove`, `axo.host.get`, `axo.host.prepareUpgrade`. Shared methods cover approved directories/work records/receipts, session start, eight chat operations, and generic runtime list/startApproved. Service negotiation/registration/discovery are separate adapters.
6. No current public terminal attachment, observation subscription/event, archive/duplicate, runtime-stop or daemon-stop method exists. Private coordination still uses prototype spellings rather than the proposed `axo._.*` cutover. Admission itself already uses an inherited owner-only channel, not a client-callable readiness claim.
7. The phone has **two distinct lanes**, not an integrated Axod conversation workbench: `PhoneWorkbenchView`/`PhoneWorkbenchState`/`ConversationClient` still use the legacy catalog/chat protocol and default `bridge.axo.leostera.dev`; Settings → `PrivateMachineBrowserView` uses the new API for machine/runtime/work-record browsing. That browser has no new-route chat/create/send/answer/cancel UI. Do not mistake old phone chat fixtures for Axod parity.
8. Commit `8044fc8` deleted tracked `service/`, `bridge/`, and `shared/` source. RFD/skill statements that those repository lanes remain intact are stale. Their historical deployed/file authority must be characterized separately; deletion of local source does not prove remote undeployment or deletion. The new API has no file routes or R2/FileIndex bindings, and `pi-axo` has no sharing/materialization implementation.
9. `AxodWorkbenchView.chatDraft` is one window-global string; `sendDraft` clears it before a dispatch result. `AxodWorkbenchCoordinator.merging` has no aggregate entry/byte eviction budget. The Mac's current structured-chat path therefore does not preserve scoped drafts or establish bounded long-lived reading.
10. Mac voice types/history/settings exist, but the Axod app has no capture key monitor or captured-terminal insertion path. Notification settings/permission queries exist, but the Axod workbench has no agent/terminal notification delivery/viewing-lease integration.
11. `WorkSessionRecord.displayName` always prefers `pi.title` to the manual name, and the new title tool unconditionally sets a valid title. Preserve Pi-owned automatic naming, but manual-name/replacement protection from R3/R9 is not supplied by that precedence.
12. The Mac app has one `NSWindow` and one coordinator holding selected-session state. Multiple app processes sharing a daemon are not proof of independent windows in one app, or same-pane renderer behavior.
