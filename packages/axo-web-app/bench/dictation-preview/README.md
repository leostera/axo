# Composer live dictation preview pilot

Question: do recent-audio previews give a useful signal while recording, without hurting the final whole-clip draft or stacking inference at Stop? Baseline: stock Axo `0f8059a8`. Candidate: `871c3529`. This is one paired pilot per fixture, not a percentile or quality qualification. Check preview appearance and wording as well as Stop click → visible draft.

`results/paired-10s.json` records the exact source SHAs, fixture manifest and hashes, diagnostics and excerpts. Both targets run the real composer, model worker, and AudioWorklet in desktop Chrome. Only the physical audio source was substituted, using the shared 1× synthetic WAV fixture. `streaming` is the upstream runner's label for the candidate; both finals run batch inference.

To reproduce, install dependencies in both clean target checkouts, extract the shared harness (`run.mjs`, `page-probe.mjs`, and `metrics.mjs` from `a781b257c90cbe3d037d22cd5f3dc2f9d8f7478b`, path `packages/axo-web-app/bench/`) into a scratch directory with the workspace dev dependencies resolvable. Apply `probe.patch` with `patch -p1`. Run `node run.mjs --baseline <stock checkout> --candidate <feature checkout> --fixtures <shared v2 corpus> --out <results.json> --reps 1 --durations 10 --modes normal`. The runner obtains the verified assets during its warmup and holds the shared Chrome lock.

The final path is unchanged except for waiting for at most the single in-flight preview on the same model worker. This Parakeet.js/WASM combination cannot interrupt an active decode without destroying the warm model. Stop/Send prevents any more previews before the capture flush and ignores any late preview. Cancel can terminate the worker, and a lost preview worker can be restored from the verified local cache before finalizing. No preview can supply text to a draft or Send. Check a real microphone, slower desktops, and varied languages before claiming device-wide usefulness or latency.
